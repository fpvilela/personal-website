## Navbar

Reference:
`https://zalt.me/`

Reason:
The navbar should follow the `zalt.me` pattern because it is the strongest reference for combining identity, navigation, and action in a single header. It gives the site an immediate personal signature through the brand area, keeps the main sections easy to scan, and reserves space for a clear primary call to action. This works better for the project than a more reduced portfolio navbar, because the site needs to guide visitors toward both content and contact, not only present a minimal visual frame.

## Experience

References:
`https://santifer.io/`
`https://brittanychiang.com/`
`https://jrdan.dev/`

Reason:
The Experience section should use `santifer.io` as the visual base, while borrowing the role-first information hierarchy seen in more structured experience sections such as `brittanychiang.com` and `jrdan.dev`. This is a plausible middle ground because `santifer.io` offers the most modern and distinctive presentation style, but its experience entries do not follow a single rigid content standard across all cases. For this project, the section should keep the visual character and layout direction of Santifer while applying a more consistent structure: company logo, experience title as the main heading, company name as secondary text, supporting context such as period, and a concise description followed by related project summaries. This approach stays aligned with current portfolio conventions because it combines a modern editorial surface with a clearer and more scannable content hierarchy.

## Projects

References:
`https://santifer.io/`
`https://jrdan.dev/`

Reason:
The Projects section should use `santifer.io` as the visual base while applying a `jrdan.dev`-like structure to each item. This is the most suitable direction because Santifer provides a more modern and editorial presentation style, which keeps the section aligned with the rest of the website, while Jrdan offers a clearer and more repeatable content hierarchy for project entries. For this project, each item should follow a stable structure based on the available resume data: project title, year, summary, bullets, links, and skills. This makes the section visually expressive without losing consistency, and it supports projects that need more substance than a minimal portfolio card can provide.

## Skills and Languages

References:
`https://santifer.io/`

Reason:
The Skills section should follow `santifer.io` because it presents capabilities in a compact and modern way that feels integrated with the rest of the site instead of isolated as a technical inventory. This is the most suitable reference for the project because the overall direction of the website favors concise, well-composed sections over dense resume-style blocks. ## Closing Contact Block

References:
`https://santifer.io/`
`https://zalt.me/contact`

Reason:
This part of the homepage should not become a large standalone Contact section or a card-based contact grid. The most suitable direction for the project is a compact closing block that works as the final page ending while keeping contact visible without giving it disproportionate weight in the overall structure. This choice is better aligned with the current amount of contact data and with the broader direction of the site, which is favoring concise and integrated sections. `santifer.io` provides the best base for this lightweight closing treatment, while `zalt.me/contact` offers the clearest model for how each contact method can be presented as a labeled action instead of only as an icon. This creates a stronger middle ground for the project: more explicit and usable than icon-only links, but still lighter and more consistent than a large dedicated contact module.
